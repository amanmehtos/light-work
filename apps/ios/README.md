# Light Week on iPhone

## Status, plainly

**None of the Swift here has been compiled.** It was written in a Linux
container with no Swift toolchain and no access to the Light Minute source, so
treat it as a carefully written first draft rather than working code. Expect to
fix small things on the first build.

What exists is **LightKit** — the contract between the Light Suite apps. The
SwiftUI app itself is not written.

## LightKit

A Swift package both Light Minute and the eventual Light Week app depend on, so
neither invents its own idea of what a focus session is.

| File | What it holds |
| --- | --- |
| `Model.swift` | The domain types, mirroring `packages/core/src/entities.ts` field for field |
| `Clock.swift` | The hybrid logical clock, encoding identically to the TypeScript one |
| `Protocol.swift` | Wire types for the sync protocol |
| `LightWeekClient.swift` | Sign in, read the account, write focus sessions |

Two things in here are easy to get wrong and so are tested:

**The clock must encode identically across platforms.** The padded base-36 form
is what lets a timestamp sort as a string. If iOS pads differently, clocks sort
differently on the server and conflict resolution quietly stops matching.

**Priority 1 is urgent**, matching the p1 a user reads — the opposite of
Todoist's internal scale.

## Wiring up Light Minute

When a timer finishes:

```swift
let client = LightWeekClient(baseURL: URL(string: "https://api.lightweek.app")!,
                             token: storedToken)

try await client.log(FocusSession(
    taskId: selectedTask?.id,
    startedAt: startedAt,
    endedAt: Date(),
    plannedSeconds: 25 * 60,
    focusedSeconds: actualFocusedSeconds,   // excluding paused time
    interruptions: pauseCount,
    outcome: wasCompleted ? .completed : .abandoned,
    source: "light-minute-ios"))
```

And to let someone pick what they are about to focus on:

```swift
let tasks = try await client.openTasks()   // open only, urgent first
```

That is the whole integration. Light Week does the rest: it shows accumulated
focus time on each task, and the MCP server hands that data to an agent so
planning can account for where attention actually went.

`completeTask` exists but deliberately does **not** handle recurrence — a
recurring task completed through it is marked done rather than rescheduled.
Recurrence lives in `@light/client-sdk`, and Light Minute has no business
rescheduling someone's repeating task.

## What still needs doing

1. **Compile it.** On a Mac with the Light Minute repo attached, so the shared
   package can be wired in properly rather than guessed at.
2. **The SwiftUI app.** The current client is read-then-write against the
   server; a real app wants the local-first replica the web client has — the
   store, the merge rule and the queue, ported from `@light/core`.
3. **Token storage.** The client takes a token; where it comes from is the
   app's problem, and it belongs in the Keychain with an App Group so Light
   Minute and Light Week share one sign-in.
4. **Cross-platform clock tests.** The Swift tests check the encoding against
   fixed expectations; they should check against vectors generated by the
   TypeScript implementation, so the two cannot drift.
